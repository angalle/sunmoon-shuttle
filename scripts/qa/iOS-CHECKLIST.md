# iOS 경로 사람 체크리스트 (T9 · docs/03 AC-7)

작성: **AppDev-QA** · 2026-10-05 · 대상 빌드: 로컬 `npm run build` 산출물(`dist/`)
배포본: https://angalle.github.io/sunmoon-shuttle/ (Pages 하위 경로 · CDN 캐시 최대 10분 → 배포 직후엔 새로고침 1회)

> **판정은 총괄이 한다.** 이 문서는 "자동화가 불가능한 항목"을 사람이 실기기에서 확인하기 위한 절차·기대값 목록이다.
> 자동 검증(아래 도구 3종)은 기계 판정 가능한 계약만 다루고, **아래 항목을 통과로 간주하지 않는다.**

## 0. 이 체크리스트가 필요한 이유 (한계 명시)

- 이 머신에는 **iOS 시뮬레이터·Xcode 전체가 없다**(`docs/00 §7` 실측 · CLT 만 설치). Safari/WebKit 엔진으로 이 앱을 띄울 수단이 없다.
- 따라서 T9 의 자동 도구는 **Chrome(Blink) 을 iPhone 뷰포트·iPhone UA·standalone 모드로 태워** 기계 검증 가능한 부분만 실측한다.
  Blink 로 확인한 "manifest 파싱·SW 등록·오프라인·safe-area 토큰 배선"은 계약의 **필요조건**이지 WebKit 실동작의 증명이 아니다.
- 홈 화면 추가·아이콘 렌더·전체화면 크롬은 **OS UI 조작**이라 헤드리스 브라우저에 존재하지 않는다(원리적으로 자동화 불가).

## 2. 사람 체크리스트 (실기기 iPhone/iPad Safari)

각 항목의 "자동화 불가 사유"는 그 항목을 왜 도구로 대체할 수 없는지에 대한 한 줄 근거다.

### A. 홈 화면 추가(설치) — 아이콘·전체화면

| # | 절차 | 기대값 | 자동화 불가 사유 |
|---|---|---|---|
| A1 | Safari 로 배포 URL 접속 → 하단 공유 버튼 → **"홈 화면에 추가"** 선택 | 메뉴에 "홈 화면에 추가"가 있다(설치형 페이지로 인식됨) | iOS 공유 시트는 OS UI — 헤드리스 브라우저에 해당 표면이 존재하지 않는다 |
| A2 | 추가 후 홈 화면 확인 | 아이콘이 **기본 스크린샷/회색 사각형이 아니라** 앱 아이콘(180x180 apple-touch-icon)이다 · 라벨이 **"셔틀버스"** | 아이콘 합성은 SpringBoard(OS) 렌더 결과 — 브라우저 DOM 밖이다 |
| A3 | 홈 화면 아이콘 탭 | 주소창 없는 **전체화면**으로 열린다 · 최초 1회 설치 안내 배너가 보인다 | 홈 화면 실행(standalone 크롬)은 OS 런처 동작 — 도구는 `--app=` 로 표시모드만 모사한다 |
| A4 | 다시 아이콘 탭 → 앱 안에서 설치 안내 닫기 → 재실행 | 설치 안내가 **다시 뜨지 않는다**(localStorage 1회) | 닫기 → 재실행은 실 세션·실 저장소가 필요(자동 스모크는 별도 프로필이라 매번 초기 상태) |

### B. 전체화면 레이아웃(노치·주소창)

| # | 절차 | 기대값 | 자동화 불가 사유 |
|---|---|---|---|
| B1 | 세로로 연 상태에서 상단 노치·하단 홈 인디케이터 확인 | 헤더/표가 노치·홈 인디케이터에 **가리지 않는다**(여백 ≥ 안전영역) | `env(safe-area-inset-*)` 는 실 기기의 물리 노치에서만 0이 아닌 값이 나온다 (CDP `Emulation.setSafeAreaInsets` 는 이 Chrome 에서 미지원 → 도구는 토큰 주입으로 배선만 검증) |
| B2 | 기기를 가로로 회전 | 좌우 노치 영역도 가리지 않는다 · 레이아웃이 깨지지 않는다 | 회전·물리 안전영역은 실기기 전용 |
| B3 | 페이지 끝까지 스크롤 | 배경이 하단까지 채워진다(흰/검 여백 없음) — iOS 주소창 축소/확대(동적 vh) 대응 | Safari 툴바의 동적 높이는 WebKit 런타임에서만 재현된다 |

### C. 오프라인 (비행기 모드) — AC-6

| # | 절차 | 기대값 | 자동화 불가 사유 |
|---|---|---|---|
| C1 | 홈 화면 아이콘으로 **한 번 정상 실행**(캐시 채움) → 제어센터에서 비행기 모드 ON → 앱 완전 종료 후 다시 실행 | 첫 화면(평일 시간표)이 뜬다 · 빈 화면/크래시 없음 | 비행기 모드 토글은 OS 설정 — 도구는 CDP `Network.emulateNetworkConditions(offline)` 로 네트워크만 끊어 모사한다(WebKit 아님) |
| C2 | 오프라인에서 요일 탭(평일/토/일) 전환 | 표가 즉시 바뀐다(서버 왕복 없음) · 행 수가 저장된 계약과 일치 | (C1 과 같은 이유) |
| C3 | 오프라인에서 다음 버스 카드 확인 | 카운트다운이 계속 갱신된다(1분 단위) | 실기기 시계·타이머 필요 |
| C4 | 캐시가 만료(24h 초과)된 상태로 오프라인 실행 | 데이터는 그대로 보이고 **"24시간 초과"** 류 문구로 신선도를 알린다(색만이 아니라 문구) | 시각 주입은 도구가 `?now=` 로 가능하지만 실기기 문구 렌더·폰트 확인은 눈으로 봐야 한다 |

### D. 카운트다운 정확도

| # | 절차 | 기대값 | 자동화 불가 사유 |
|---|---|---|---|
| D1 | 기기 시계와 앱 카운트다운을 같은 시각에 대조(2회, 최소 1회는 자정 전후) | 남은 시간이 기기 시계와 일치(±1분) · 자정을 넘겨도 다음 운행일 계산이 맞다 | 실기기 로컬 시계 + 자정 경과 관찰이 필요(도구는 `?now=` 주입으로 결정적으로만 계산) |
| D2 | 시간표 **마지막 차 이후** 시각으로 확인 | "오늘 운행 종료/다음 운행일" 안내가 뜬다(빈 카드·오류 화면 아님) | 실기기 시간대·시각 조작 필요(도구는 주입 시각으로 계산값만 확인) |

### E. 한/영 · 다크모드 · 접근성 스팟체크

| # | 절차 | 기대값 | 자동화 불가 사유 |
|---|---|---|---|
| E1 | 시스템 설정에서 다크모드 전환 | 배경/글자 색이 따라오고 대비가 유지된다(읽힌다) | WebKit 의 `prefers-color-scheme` + 실물 디스플레이 색 판단 필요 |
| E2 | 가로 회전 후 본문 글자 관찰 | 글자가 **자동 확대되지 않는다**(`-webkit-text-size-adjust`) | iOS 전용 렌더 동작 |
| E3 | VoiceOver 로 요일 탭·다음 버스 카드 탐색 | 순서·이름이 읽히고, 상태(운행 중단 등)가 색이 아니라 문구로 전달된다 | 스크린리더는 OS 기능 |

### F. iOS 특이 환경

| # | 절차 | 기대값 | 자동화 불가 사유 |
|---|---|---|---|
| F1 | Safari **개인정보 보호 브라우징**(프라이빗 모드)에서 접속 | 앱이 정상 표시된다(저장소 차단 시 네트워크 경로로 동작) | 실제 Safari 프라이빗의 저장소 정책은 WebKit 전용 — 도구는 `indexedDB` 제거로 근사 모사했다(`T9-5` 스크린샷) |
| F2 | 로우 파워 모드 / 저전력 상태에서 실행 | 앱이 뜨고 SW 가 등록된다 | OS 전원 정책 |
| F3 | (선택) iPad 가로 화면 | 레이아웃이 넓은 폭에서도 깨지지 않는다(최대 64rem 중앙 정렬) | 실기기 |
