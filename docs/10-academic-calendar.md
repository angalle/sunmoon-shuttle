```
1) 셔틀 안내문 dateRules (no-service / alternate-schedule)   ← 정본, 지금과 동일
2) 학사일정 academicEvents
```

| 단계 | 담당 | 파일 |

| 분류(`kind`) 초안 | 규칙 패턴표(`CALENDAR_RULES`) | 같은 파일 |

### 6-2. 분류표 (`kind`) — 규칙 파서의 문자열 패턴

| kind | 일정명 패턴(예) | 쓰임 |
|---|---|---|
| `holiday` | 신정 · 설날 · 삼일절 · 어린이날 · 부처님오신날 · 현충일 · 광복절 · 추석 · 개천절 · 한글날 · 성탄절 · `대체공휴일` · `연휴` · 개교기념일 · 근로자의날 · `선거` | §5-2 확인 필요 표시 |
| `observance` | 참부모의 날 · 참자녀의 날 (학교 기념일 — 학사력에 실려 있음, 휴교 여부 불명) | `holiday` 와 같은 `확인 필요` 표시 · 셔틀 안내문에 나오면 그쪽을 따른다 |
| `vacation-start` | `방학` + `시작`(예: 동계방학/계절학기 시작) | 방학 기간 시작 |
| `semester-start` | `개강일` (원문: `개강일, 학기개시일, 입학일`) — `학기개시 30/60/90일` 같은 경과일 표기는 제외 | 직전 방학의 끝(전날) |
| `semester-end` | `종강` | 학기 끝 교차검증 |
| `exam` | 중간고사 · 기말고사 | 안내줄 시험 예고·기간(§7) |
| `ignored` | 그 외(입시·성적·등록·수강신청 등) | **저장은 하되 화면 미노출**(분류 누락 감시용) |

- 분류는 **위에서부터 먼저 맞는 것 하나**(기존 `NOTICE_RULES` 와 같은 방식). 어떤 패턴에도 안 맞으면 `ignored` 로 두고 경고로 집계한다(조용히 버리지 않는다).

### 6-3. 연도 추론
- 제목 `2026학년도 학사력` 의 연도 = 3~12월 블록의 연도. 연도가 적힌 블록 머리글(`2027년 1월 / JANUARY`)은 그 연도를 쓴다.
- 날짜 형식: `D(요일)` 또는 `D(요일)~D(요일)`(같은 달 안 · `~` 뒤 공백 허용 — 원문 `3(화)~ 9(월)`).
- **요일이 실제 달력과 맞지 않으면 즉시 실패**(조용한 손상 금지). 예: `2026-12-15` 는 화요일이어야 한다.

### 6-4. 방학 기간 산정 (`terms[vacation]`)
- `start` = `vacation-start` 의 날짜.
- `end` = 그 다음 `semester-start` 의 **전날**. 하계방학은 같은 학사력의 2학기 개강(9.1)으로 닫히지만, **동계방학은 다음 학년도 학사력이 있어야** 닫힌다 → 없으면 `null`(추측 금지) · 배너는 "12.15(화)부터 방학" 형태로 시작일만 보인다.
- 교차검증: `vacation-start` 전날이 `terms[semester].end` 와 다르면 **경고**(발행은 막지 않음, 로그·`needsReview`).

### 6-5. 계절학기·방학 시간표는 셔틀 시간표 페이지가 정본
- 방학·계절학기 **시간표 자체**(편·시각)는 지금처럼 **셔틀 시간표 페이지 스냅샷**을 파싱해서 들어온다(결정 §11-3). 학사일정은 시간표를 만들지 않는다 — **기간과 전환일**만 준다.
- 그 페이지는 학교 담당자가 손으로 갱신하므로 **전환일보다 늦게** 바뀔 수 있다. 그 틈을 아래 §6-7 로 드러낸다.

### 6-6. 시험 기간
- `kind=exam` 의 `start`/`end` 를 그대로 쓴다(중간고사·기말고사). 화면 노출은 §7.
- 시험 기간은 운행 판정에 영향을 주지 않는다(표시 전용).

### 6-7. "시간표 갱신 지연" 판정
- 조건: 오늘 ≥ `vacation-start` **그리고** 발행본의 `terms[semester].end` < 오늘 **그리고** 발행본에 방학 시간표 기간(`terms[vacation].start`가 셔틀 페이지에서 온 값)이 없음.
- 이때 화면은 **마지막 학기 시간표를 계속 보여 주되**, §7 의 경고 1줄을 띄운다(빈 화면 금지 · 추측으로 방학 시간표를 만들지 않음).
- 같은 조건을 추출기(`extract.yml`)도 판정해 **런 요약에 경고**를 남긴다 → 사람이 "방학 시간표 스냅샷을 새로 저장할 때"임을 알게 된다.

### 6-8. 스키마 버전 — **3 유지**(T42 결정)
- `academicEvents` 는 **선택 필드 추가**다. 앱 파서(`normalize.ts`)는 모르는 최상위 필드를 무시하므로(실측: 새 발행본을 그대로 파싱 성공) 버전을 올릴 이유가 없다.
- 버전을 올리면 소비자 게이트·캐시 무효화·테스트 10여 곳이 같이 움직여야 하고, T16 사고(게이트 미확장으로 폴백 붕괴)와 같은 위험만 생긴다 → `schemaVersion: 3` 그대로.
- `contentHash` 는 `academicEvents` 가 있을 때만 그것을 포함한다(학사력이 없는 실행의 해시는 예전과 같다). 계약 검증(`verify_contract.mjs`)도 통과.
- 앱이 학사일정을 **읽기 시작하는** T44 에서 `normalize.ts`·`model.ts` 에 선택 필드로 추가한다(없으면 기본 동작).

## 8. 검증 (발행 전 기계 판정)

1. **원문 앵커**: 모든 `label`·날짜 토큰이 스냅샷 텍스트에 존재.
2. **요일 일치**: 추론한 날짜의 요일 = 원문 요일(100%).
3. **분류 커버리지**: `holiday` 패턴 목록의 공휴일이 해당 월 스냅샷에 있으면 반드시 `holiday` 로 분류(누락 0).
4. **교차검증**: 학기 끝 ↔ `vacation-start` 전날, 안내문 휴일 ↔ 학사일정 공휴일 — 불일치는 경고로 리포트.
5. **드리프트 게이트**(`docs/08 §7` 확장): 직전 발행본 대비 `academicEvents` 의 `holiday`/`vacation-start` 가 사라지면 발행 보류.

## 10. 수용 기준 (AC-AC = Academic Calendar)

- **AC-AC1** 스냅샷의 공휴일·방학 시작·학기 시작/끝이 `academicEvents` 에 **누락 0**, 요일 불일치 **0**.
- **AC-AC2** 2026-2학기 데이터에서 `terms[vacation].start = 2026-12-15` 가 채워지고 `needsReview` 가 해제된다(끝은 다음 학기 스냅샷이 있을 때만).
- **AC-AC3** `?now=2026-12-10` → 방학 예고 1줄 · `?now=2026-12-16` → 방학 기간 1줄 · `?now=2026-12-25` → `성탄절 · 운행 여부 확인 필요` 1줄, 목록은 숨기지 않음.
- **AC-AC4** 셔틀 안내문 `no-service` 날짜(예: 10.09 한글날)는 **기존 표시 그대로**이고 학사일정 문구가 겹치지 않는다.
- **AC-AC5** `?now=2026-12-05` → `12.08(화)부터 기말고사` · `?now=2026-12-10` → `기말고사 기간 (12.08~12.14)` 1줄(방학 예고와 같은 날이면 **2줄까지** 허용, 순서: 시험 → 방학).
- **AC-AC6** 학기 끝이 지났는데 방학 시간표 스냅샷이 없는 데이터(`?now=2026-12-16`, 셔틀 페이지 미갱신)에서 학기 시간표를 그대로 보여 주고 `방학 시간표가 아직 반영되지 않았을 수 있어요` 경고 1줄 · 추출 런 요약에도 같은 경고.
- **AC-AC7** v3 데이터(학사일정 없음)로도 렌더 회귀 0 · 고정 영역 128~136px · 가로 스크롤 0.

## 11. 결정 사항 (2026-11-08 사용자)

1. **공휴일 표시 수위 → 제안대로 유지.** 안내문에 없는 공휴일은 `확인 필요`로만 표시하고 운행 판정은 바꾸지 않는다(§5).
2. **시험 기간 → 보여 준다.** 시험 예고(3일 전)와 기간 중 안내줄 1줄(§6-6 · §7 · AC-AC5).
3. **계절학기 셔틀 → 아마 있다. 시간표는 셔틀 시간표 페이지 파싱으로 들어온다.** 다만 사람이 페이지를 갱신하므로 늦을 수 있다 → 학사일정의 방학 시작일로 **갱신 지연을 감지해 경고**한다(§6-5 · §6-7 · AC-AC6).
4. **수집 방식 → 위임받음.** 처음엔 안 A(월별 HTML)로 정했으나, 월별 요청이 막히고 사용자가 "한 번에" 를 원해 **안 B(연간 학사력 파일 1개)로 개정**(§4).
