# 00 — 요구사항 정의 (선문대 셔틀버스 시간표 앱)

작성: ProjectCreator(총괄) · 2026-10-05 · 대체 대상: `angalle/SM.Univ-Bus-Schedule`(2017, Java Android)

## 1. 목표
선문대학교 **셔틀버스 시간표**를 학생·교직원이 **오프라인에서도 즉시** 확인할 수 있게 한다. 원본 페이지 수집·정규화·캐싱을 **사람 손 없이·운영비 0원**으로 유지한다.

## 2. 사용자 / 이해관계자
| 주체 | 필요 |
|---|---|
| 재학생 (주 사용자) | 등교·하교 시간 확인, **다음 버스까지 남은 시간**, 지하철(아산역·탕정역) 연결 파악 |
| 교직원·방문객 | 노선·정류장·소요시간 확인 |
| 학교(콘텐츠 소유자) | 원본 출처 표시, 서버 부하 최소, **비공식 앱임을 명시** |
| 스토어 심사(Play/App Store) | 개인정보 수집 0 고지, 개인정보처리방침 URL, 콘텐츠 등급 |
| 개발자(사용자) | 유지비 0, 학기 개편 시 자동 반영 |

## 3. 기능 요구
### MUST
| # | 요구 | 비고 |
|---|---|---|
| F1 | **요일 구분**: 평일 / 토요일 / 일요일 시간표 | 원본 탭 3개 |
| F2 | **노선별 시간표 표**: 순번 · 출발(캠퍼스) · 출발(역) · 도착 · 특이사항 — **노선·요일별로 열 구성이 다르다**(T1 실측: 평일 5·7·8열, 토요일 4열=특이사항 열 없음) | 원본 열 구조 유지 · 병합 셀(`colspan`)은 **하나의 값**으로 파싱 |
| F2b | **운행 중단 노선 표시**: **천안캠퍼스는 2024-2학기부터 운행 중단**(원본에 표 0개·문구만) → 목록에서 **조용히 숨기지 않고** 상태·안내 문구를 표시(문의 (주)모모관광 041-544-8710) | 원본 문구를 그대로 인용 |
| F3 | **다음 버스 카운트다운**: 현재 시각 기준 가장 가까운 출발과 남은 시간 | 요일·공휴일 규칙 반영 |
| F4 | **오프라인 전면 동작**: 네트워크 없이 앱 실행·조회 | 캐시(Service Worker + IndexedDB) |
| F5 | **신선도 표시**: 원본 "최근 업데이트"(예: 2026-08-20) + 우리 수집 시각 | 사용자가 데이터 나이를 알 수 있게 |
| F6 | **원본 출처 링크** + 비공식 고지 | 저작권·신뢰 |
| F7 | **운행 안내 반영**: 공휴일·연휴·개교기념일 운행 없음/대체 시간표, 요금·승차 위치 안내 | 원본 안내문 파싱 |
| F8 | **수집 실패 시 폴백**: 마지막 정상 데이터로 계속 동작(빈 화면 금지) | 모니터링 §복구 |

### SHOULD
| # | 요구 |
|---|---|
| S1 | 즐겨찾기(노선·정류장) 저장 — 로컬만 |
| S2 | 출발 **N분 전 로컬 알림**(푸시 서버 없이) |
| S3 | 다크 모드 · 큰 글씨(접근성) |
| S4 | 시내버스 참고 정보(970·971·700·777·1200·순환5 노선 · 승강장 안내) |
| S5 | 설치형(PWA) — 홈 화면 아이콘·전체화면 · 한/영 |

### MAY
| # | 요구 |
|---|---|
| M1 | 학사일정 연동으로 휴일 자동 처리 |
| M2 | 정류장 위치 안내(지도 링크) |
| M3 | 위젯(Android) / 잠금화면 요약(iOS는 제약) |

## 4. 비기능 요구 (측정 가능하게)
| 항목 | 목표 |
|---|---|
| 첫 화면 표시 | 캐시 기준 **≤ 1.0s** (중급 Android) |
| 번들 크기 | 초기 전송 **≤ 300KB gzip** |
| 데이터 신선도 | 수집 성공 시 **≤ 24h** (하루 2회) |
| 오프라인 | 비행기 모드에서 **모든 MUST 기능 동작** |
| 크롤 예의 | **하루 ≤ 4회**, User-Agent 명시, `If-Modified-Since`/ETag 사용, 요청 간 지연 ≥ 1s |
| 운영비 | **0원** — 과금 리소스(서버·DB·CDN·함수) 사용 0 |
| 개인정보 | **수집 0** (계정·위치·기기식별자 없음), 로컬 저장만 |
| 접근성 | 대비비 ≥ 4.5:1 · 터치 타깃 ≥ 48px · 색만으로 정보 전달 금지 |
| 호환 | iOS Safari 16+ · Android Chrome 110+ · 데스크톱 Chrome/Safari (실측 검증) |

## 5. 수용 기준 (AC) — 검수는 이걸로 판정한다
| AC | 기준 | 판정 방법(총괄 직접) |
|---|---|---|
| **AC-1** | 파서가 원본 HTML 픽스처 **3종(평일·토·일)** 에서 시간표를 **표 단위로 정확히** 추출 | 골든 JSON 대조: 행 수·각 셀 값 100% 일치 |
| **AC-2** | 같은 HTML 입력 → **같은 JSON**(결정성) | 2회 실행 해시 동일 |
| **AC-3** | **다음 버스 계산**이 경계에서 정확(자정·요일 전환·공휴일·운행 없음 구간) | 표 기반 단위 테스트 케이스 ≥ 12개 통과 |
| **AC-4** | 원본이 바뀌면 **자동 반영**(변경 시에만 커밋) | Actions 로그 + 커밋 diff, 무변경 시 커밋 0건 |
| **AC-5** | 수집 실패 시 **마지막 정상 데이터**로 동작(빈 화면·크래시 0) | 실패 주입 테스트 + 스크린샷 |
| **AC-6** | **오프라인**에서 실행·조회·카운트다운 동작 | 비행기 모드 스크린샷 3장 |
| **AC-7** | **iOS Safari + PWA 홈화면** · Android Chrome 동작 | 기기/시뮬레이터 스크린샷 |
| **AC-8** | **운영비 0** · 개인정보 수집 0 실측 | 과금 리소스 목록 0건 · 네트워크 요청 목록에 추적/광고 도메인 0 |

## 6. 범위 밖 (명시)
- 실시간 버스 위치·도착 예측(GPS 연동), 예약·결제, 푸시 **서버** 운영
