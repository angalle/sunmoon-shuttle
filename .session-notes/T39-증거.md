## 0. 무엇이 문제였나

`public/sw.js` 의 `SW_VERSION` 을 **사람이 손으로** 올리는 구조였다. T32 에서 한 번 올린 뒤
T30~T38 빌드가 여러 번 있었지만 값이 그대로였고 → 서비스워커가 **stale-while-revalidate 로 옛 셸을 먼저 응답** →
사용자 폰에는 옛 UI(`전체` 칩 등)가 계속 보였다. **사람 손에 의존하는 한 재발한다**는 것이 §16-3 의 판단이다.

## 1. 무엇을 바꿨나 (구조)

| 파일 | 변경 |
|---|---|
| `public/sw.js` | `const SW_VERSION = '2026-10-09.1';` → `const SW_VERSION = '__SW_VERSION__';` (빌드가 치환하는 **자리표시자**). 헤더 주석도 "배포 시 손으로 올린다" → "자동 주입(docs/07 §16-3)"으로 정정 |
| `vite.config.ts` | 플러그인 `sunmoon-shuttle:sw-auto-version` 추가 — ① `configResolved` 에서 버전 계산 ② `configureServer`(dev) 는 `/sw.js` 요청을 같은 규칙으로 치환해 서빙 ③ `writeBundle`(build) 은 `dist/sw.js` 에 치환본을 쓰고 **되읽어 검증**(버전 미주입·자리표시자 잔존이면 throw → 빌드 실패) |
| `scripts/serve-demo.sh` | ④ 자체 점검의 SW 판정 기준 변경(수동 범프 폐기로 "public == dist == 서빙본" 비교가 성립하지 않음) → "public=자리표시자 · dist=주입된 실제 값 · 서빙본=dist" |
| `tests/web/serviceWorker.test.ts` | 버전 계약 테스트를 새 계약으로 갱신(자리표시자 1개 + 주입 주체 존재 + `dist/sw.js` 주입 형식) |
| `docs/07-mobile-ux.md` §14-2 | 규칙 1줄: "`SW_VERSION` 을 올린다" → "**자동 주입**(§16-3)" |
| `scripts/t39_sw_cache_swap.mjs` | 신설 — §2의 실측 자동화(옛 배포→새 배포 교체 시나리오를 헤드리스 Chrome 으로 재현) |

버전 형식: `YYYYMMDD-HHmmss-mmm-<git short SHA>` (예: `20261012-110529-056-03a10a5`).
**밀리초를 넣는 이유**: 빌드가 빨라 같은 초에 두 번 끝나도 값이 달라져야 한다(아래 AC-U16-4a 실측 참조).
`git` 이 없으면 `-nogit` 접미사로 떨어지고 빌드는 막지 않는다.

**설계 판단(보고)**: 자리표시자는 `public/sw.js` 안에 **정확히 1개**여야 하며, 0개/2개면 빌드가 **실패**한다.
(실제로 이 가드를 개발 중에 한 번 밟았다 — 주석에도 `__SW_VERSION__` 문자열을 썼다가 빌드가 즉시 실패했고,
주석 문구를 고쳐 통과시켰다. 조용히 넘어가지 않는다는 증거다.)
