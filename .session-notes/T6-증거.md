## 3. T5 도구 수정(불가피 · 사유 기록)

`scripts/render_smoke.mjs` 의 "데이터 로드 실패 시 오류 UI" 단계는 **캐시가 채워진 상태**에서는 더 이상 성립하지 않는다(T6 이후 실패는 캐시 폴백이 정상 동작). 의도를 유지하려고 실패 주입 **직전에 SW 해제 + SW 캐시 삭제 + IndexedDB 삭제 + `sw.js` 404** 를 넣어 "캐시가 전혀 없을 때"를 만들었다(주석에 사유 명시). 수정 후 `RENDER SMOKE: PASS (exit 0)` — T5 의 24항목은 그대로 통과한다.
추가: 앱은 페이지 로드마다 SW 를 재등록하므로 CDP 요청 차단으로는 SW 를 끌 수 없다(브라우저가 직접 받는 스크립트 요청). 그래서 스모크 서버가 `sw.js` 를 404 로 답하는 플래그를 두었다 — 이 사실 자체가 검증 결과다.

## 4. 한계·가정 (정직하게)

1. **`fake-indexeddb` 를 쓰지 못했다.** 카드 지시 ①은 `fake-indexeddb`(devDependency)를 쓰라고 했지만, 이 실행 환경의 패키지 보안 게이트가 설치를 차단했다(원문: `npm install --save-dev fake-indexeddb@6.2.5` → "BLOCKED: Security scan — [MEDIUM] Package threat intelligence could not be completed … ecosyste.ms metadata lookup deadline exhausted", 헤드리스라 승인 불가). 대안으로 저장소 안에 **최소 IndexedDB 페이크**(`tests/support/fakeIndexedDb.ts`, 의존성 0)를 두고 어댑터가 실제로 쓰는 API 표면만 구현했다. 페이크는 **실패 주입**(open 실패·응답 없음→타임아웃·get 실패·put 실패)을 지원해 "읽기 실패 시 안전 폴백"을 실제로 검증한다 — `fake-indexeddb` 로는 이 주입이 번거롭다. 한계: 실 브라우저 IndexedDB 와의 동일성은 보장되지 않는다 → 실제 브라우저 경로는 `scripts/offline_smoke.mjs` 가 헤드리스 Chrome 으로 검증했다(SW 캐시·IndexedDB 레코드 실측 포함).
2. `sw.js` 캐시 만료 판정은 하지 않는다(계약대로 앱 계층 담당). SW 는 자산 바이트만 보관한다.
3. SW 업데이트 반영: `SW_VERSION` 상수를 올리는 것이 정본이고, `skipWaiting`+`clients.claim` 으로 배포 직후 이전 버전 노출을 줄였다. 다만 Pages CDN 캐시(최대 10분) 때문에 **배포 직후 첫 방문**은 이전 셸을 볼 수 있다(1회 새로고침 후 최신). 실측은 로컬 빌드 기준이다.
4. 스모크는 헤드리스 Chrome(로컬 `dist`, `127.0.0.1`)에서 실행했다. 실기기(iOS/Android) 오프라인 동작은 T8·T9 범위다.
5. `npm run test` 의 171개에는 같은 워크스페이스에서 동시 작업 중인 T7 의 `tests/web/*`(매니페스트·아이콘·토큰 검사)이 포함된다. 내 실행 시점에는 0 fail 이었다.
6. `src/domain` 수정 0줄(위 diff 증거). 결과적으로 만료 정책을 도메인이 아니라 `src/application/cache/` 에 두었다 — 도메인 동결이 풀리면 옮길 수 있게 정책을 파일 1개로 격리해 두었다.
